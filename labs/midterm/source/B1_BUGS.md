# B1 · บันทึกการแก้บั๊ก (กรอกให้ครบทั้ง 6 จุด)

> แต่ละบั๊กให้เขียน 4 อย่าง: ไฟล์ · บรรทัด · สาเหตุ (ทำไมทำงานผิด) · แก้อย่างไร
> เขียนด้วยคำของตัวเอง — จุดนี้จะถูกถามใน oral

## บั๊กที่ 1 — อาการ: Console แสดงคำเตือนเกี่ยวกับการแสดงรายการ

- ไฟล์/บรรทัด: `src/components/RequestList.jsx` บรรทัดที่ 8
- สาเหตุ: ในส่วนที่ใช้ `.map()` เพื่อวนแสดงข้อมูล `RequestCard` แต่ละรายการ ไม่มีการกำหนดค่า `key` ทำให้ React       แจ้งเตือนว่ารายการที่สร้างขึ้นควรมีค่า `key` ที่ไม่ซ้ำกัน
- แก้อย่างไร: เพิ่ม `key={request.id}` ให้กับ `<RequestCard />` เพื่อให้ React สามารถระบุแต่ละรายการได้อย่างถูกต้อง


# บั๊กที่ 2 — อาการ: จำนวนรายการที่อยู่ระหว่างดำเนินการแสดงผลคลาดเคลื่อน

- ไฟล์/บรรทัด: `src/pages/DashboardPage.jsx` บรรทัดที่ 43
- สาเหตุ: ส่วนที่ใช้ `useMemo` สำหรับนับจำนวนคำขอที่มีสถานะ `pending` ระบุเงื่อนไขไม่ถูกต้อง โดยตรวจสอบเป็น `completed` - จึงทำให้ตัวเลขที่แสดงในหน้า Dashboard ไม่ตรงกับข้อมูลจริง
- วิธีแก้ไข: ปรับเงื่อนไขการกรองให้ตรวจสอบสถานะ `pending` โดยใช้ `requests.filter((request) => request.status === 'pending').length`

## บั๊กที่ 3 — อาการ: เลือกสถานะ "รอดำเนินการ" แล้วผลลัพธ์ไม่ตรงกับตัวกรอง

- ไฟล์/บรรทัด: `src/pages/DashboardPage.jsx` บรรทัดที่ 49
- สาเหตุ: ตัวแปร `filteredRequests` มีการตรวจสอบสถานะกลับด้านจากที่ควรเป็น โดยใช้ `!==` ทำให้ระบบนำรายการที่สถานะไม่ตรงกับตัวเลือกมาแสดง
- วิธีแก้ไข: ปรับตัวดำเนินการเปรียบเทียบจาก `!==` เป็น `===` เพื่อให้แสดงเฉพาะรายการที่มีสถานะเดียวกับที่ผู้ใช้เลือก โดยใช้ `request.status === statusFilter`

## บั๊กที่ 4 — อาการ: เมื่อเปลี่ยนรหัสคำขอใน URL ข้อมูลหน้าเว็บยังเป็นรายการเดิม

- ไฟล์/บรรทัด: `src/pages/RequestDetailPage.jsx` บรรทัดที่ 26
- สาเหตุ: `useEffect` ไม่ได้กำหนด `requestId` ไว้ใน Dependency Array ทำให้เมื่อ URL เปลี่ยนไปเป็นรหัสคำขออื่น ระบบไม่ตรวจพบการเปลี่ยนแปลงและไม่โหลดข้อมูลใหม่
- วิธีแก้ไข: เพิ่ม `requestId` ลงใน Dependency Array ของ `useEffect` เพื่อให้ทำงานอีกครั้งเมื่อ ID เปลี่ยน โดยกำหนดเป็น `[requestId, reloadKey]`


## บั๊กที่ 5 — อาการ: ลบรายการแล้วข้อมูลบนหน้า Dashboard ยังไม่หายทันที

- ไฟล์/บรรทัด: `src/pages/DashboardPage.jsx` บรรทัดที่ 56
- สาเหตุ: ภายใน `handleDelete` มีการส่งค่า `requests` เดิมกลับเข้าไปใน `setRequests()` ทำให้ React ยังคงใช้ข้อมูลก่อนการลบ ส่งผลให้รายการที่ลบไปแล้วยังปรากฏบนหน้าจอจนกว่าจะรีเฟรชหน้า
- วิธีแก้ไข: เปลี่ยนค่าที่ส่งให้ `setRequests()` เป็น `nextRequests` ซึ่งเป็นข้อมูลชุดใหม่หลังจากดำเนินการลบเสร็จแล้ว โดยใช้ `setRequests(nextRequests)`

### บั๊กที่ 6 — อาการ: กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx บรรทัดที่ 65
- สาเหตุ: ฟังก์ชัน handleReset เรียกใช้ setRequests(resetRequests()) โดยไม่ได้ใส่ await เพื่อรอผลลัพธ์ข้อมูลจากฟังก์ชัน asynchronous ทำให้ state รับค่าเป็น Promise แทนที่จะเป็น Array ส่งผลให้การทำงานแสดงผลของ React พัง
- แก้อย่างไร: เปลี่ยนเป็น const resetData = await resetRequests(); แล้วค่อยอัปเดต state ด้วย setRequests(resetData)
